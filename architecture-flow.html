LeadForge Architecture Flow

Full request lifecycle: User Input → Pipeline → Gemini AI → Response → Display → Logging

React 19 Vite 8 TypeScript 6 Supabase Edge Fn Gemini 2.5 Flash Google Places API Tailwind v4 TanStack Query
⚡ Request Lifecycle Timeline

Traces a single request from browser to Gemini and back. Each node = one verifiable code reference.

01 User Input SearchForm.tsx → use-import-businesses.ts
User fills the SearchForm: keyword (e.g. "Dentists"), city, country. Form calls onSubmit({ keyword, city, country }) which triggers the React Query mutation useImportBusinesses. For analysis/enrichment/sales actions, the user clicks a button on a business card → useAnalyzeBusiness / useEnrichBusiness / useGenerateSales.
  • Import input: keyword (required), city, country
  • Analyze input: business_id only
  • Sales input: business_id + language (default 'en', supports ar, fr)
02 API Client lib/api-client.ts → supabase.functions.invoke()
api.post('import-businesses', body) calls invokeFunction() which wraps supabase.functions.invoke(). The Supabase SDK injects the user's JWT in the Authorization header automatically.
  • Format: supabase.functions.invoke(path, { method, body })
  • Error extraction: Parses FunctionsHttpError.context for error.code and error.message
  • ⚠️ console.log() still active in production — logs full API responses
03 CORS Middleware _shared/cors.ts
Every edge function runs handleCors(req) first. If req.method === 'OPTIONS', returns 200 "ok" with headers. All responses include:
Access-Control-Allow-Origin: *
Access-Control-Allow-Headers: authorization, x-client-info, apikey, content-type
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
CORS: Wide-open wildcard — restrict before production
04 Logger Initialization _shared/observability/logger.ts
createLogger(req) generates a unique X-Request-ID from headers, attaches it to every subsequent log entry and error response. Every step logs structured events (e.g. request.started, analysis.started).
05 HTTP Method Guard index.ts (each edge function)
If the request method doesn't match (e.g. GET on an import endpoint), immediately returns:
405 METHOD_NOT_ALLOWED — "Method not allowed"
06 Body Parsing & Validation _shared/response.ts → req.json()
For POST requests, the body is parsed. Missing required fields return immediately:
400 BAD_REQUEST 400 MISSING_FIELD
  • Import: requires project_id + keyword
  • Analyze/Enrich/Sales: requires business_id
  • Sales also validates language ∈ [en, ar, fr]
07 Authentication _shared/auth/context.ts → authenticate()
authenticate(req) extracts the Authorization header, creates a Supabase client scoped to the user's JWT, then calls getUser(token) to validate. Returns an AuthenticatedContext:
{ user: User, // Authenticated user
client: Supabase, // RLS-enforced (user's JWT)
service: Supabase, // Admin client (bypasses RLS)
logger: Logger }
401 UNAUTHORIZED_NO_AUTH_HEADER 401 UNAUTHORIZED_INVALID_TOKEN
08 Ownership Verification _shared/auth/verification.ts
verifyBusinessOwnership(ctx, id) or verifyProjectOwnership(ctx, id) queries using the user-scoped client (RLS enforced). If the row isn't found or isn't owned, throws: FORBIDDEN_OR_NOT_FOUND → 403 RLS policy: projects.owner_id = auth.uid() → businesses.project_id → projects.
09 Rate Limiter _shared/services/rate-limiter.ts → increment_usage RPC
RateLimiter.checkAndIncrement(userId, type, maxLimit) calls the Postgres RPC increment_usage(p_user_id, p_usage_type, p_max_limit).
  • Import: maxLimit = 100 per day per user
  • Gemini (Analysis): maxLimit = 50 per day per user
  • Failure mode: Fail Open — if RPC fails, the request proceeds (beta mode)
429 RATE_LIMIT_EXCEEDED
⚠️ SECURITY: increment_usage is SECURITY DEFINER without search_path — risk of privilege escalation
10 IMPORT PIPELINE import-businesses/index.ts → ImportService → BusinessImporter
Full import pipeline (synchronous, v1):
  1. Google Places Search — TextSearch with FIELD_MASK (Basic+Contact), ≤60 results (3 pages × 20)
  2. Location Validation — skips businesses whose address doesn't reference the requested city
  3. Deduplication — by place_id → website → phone, scoped by owner_id via projects!inner
  4. Health Scoring — weighted: website 25 + phone 20 + rating 10 + reviews>10 10 + reviews>50 5 + address 10 + category 10 + coordinates 10 = 100
  5. Status Assignment — score ≥ 50 AND has website → READY_FOR_ANALYSIS, else NEW
  6. Session Tracking — creates import_sessions row with per-batch counters (new/updated/failed)
Provider: GOOGLE_PLACES  |  Max results: maxImportPages × 20  |  API cost tracked via CostTracker
11 ENRICHMENT PIPELINE enrich-business/index.ts → EnrichmentService → NativeScraper → DetectionEngine
Website scraping + capability detection:
  1. Native HTTP Scraper — crawls 5 sub-pages: /, /about, /contact, /services, /booking. Fetch-only (no headless browser), 10s timeout per page, robots.txt respecting.
  2. Regex HTML Parser — extracts: title, meta, phone, email, address, social links, WhatsApp, text chunks, links. No DOM library → SPA sites yield empty text.
  3. Detection Engine (8 detectors): Analytics Booking Chatbot Contact Pixel Social Tech Stack WhatsApp
  4. Persist — normalized rows → website_pages, website_content, business_capabilities, business_technologies, contacts
12 Canonical Profile Builder _shared/services/profile-builder.ts
Merges all data into a single CanonicalBusinessProfile:
  • Content caps: HOME 4000 | SERVICES 3000 | ABOUT 1500 | CONTACT 1000 | BOOKING 1000 chars
  • Knowledge Score (0–100): website +30 | scraped pages +20 | contacts +20 | address +10 | tech +10 | reviews +10
  • Analysis Source: FULL_WEBSITE | PARTIAL_WEBSITE | GOOGLE_PLACES_ONLY
  • Confidence (hardcoded): extraction 90 | detection 95 | overall 92
  • Signals: BOOKING_MISSING, WHATSAPP_MISSING, CHATBOT_MISSING, NO_SOCIAL_LINKS, SSL_MISSING
  • Aggregate Hash: SHA-256 of the entire profile for cache invalidation
13 Analysis Cache Check _shared/repositories/analysis-repo.ts
Compares aggregate_hash with the most recent stored analysis. If identical AND analysis_items exist (ghost-row guard added in Phase 1.9), skips Gemini and recomputes priority from cached score. Otherwise proceeds to the AI call.
14 PROMPT CONSTRUCTION _shared/ai/prompt-builder.ts → consultantV2.systemInstruction()
User prompt: PromptBuilder.buildUserPrompt(profile) serializes: identity, reputation, digitalPresence (pages + content with caps), contacts, technologies, verified_facts, knowledge_score.

System instruction: Injected by consultantV2.systemInstruction(context) — receives offer templates as context and appends them to the prompt. Contains 6 critical rules + 6 analysis steps + strict JSON output schema. See full prompt layers in the Prompt Section below.
consultant-v2.2-hybrid temperature: 0.2 timeout: 90s responseMimeType: application/json

16 AI Output Validation _shared/ai/validator.ts → AiValidator.validate()
Validates the raw Gemini JSON against strict rules before persisting. Coerces invalid values instead of failing when possible:
  • Required strings: business_summary, sales_angle, recommended_offer, score_explanation, confidence_score
  • lead_score: number 0–100 | confidence_score: HIGH | MEDIUM | LOW
  • Arrays: strengths, weaknesses, automation_opportunities, ai_opportunities — each item validated as EvidenceItem
  • Invalid evidence_level → coerced to MEDIUM | Invalid impact_type → coerced to Operations
  • positive_signals / negative_signals default to [] (excluded from responseSchema to avoid "too many states" error)
17 Priority Calculator _shared/services/priority-calculator.ts
Deterministic, no LLM — computes from contact channels + lead score:
  • Sales Readiness (0–20 cap if no contacts): EMAIL +25 | PHONE +20 | WHATSAPP +20 | LINKEDIN +10 | Website +15 | Address +10
  • Priority Score: 0.55 × leadScore + 0.45 × salesReadiness
  • Priority Tier: IMMEDIATE ≥90 | HIGH ≥70 | MEDIUM ≥50 | LOW < 50
  • Next Best Action: CALL (phone + score≥70) → EMAIL (professional domain) → WHATSAPP → EMAIL (any) → CALL (phone only) → IGNORE (no contacts)
18 Save Results & Track Costs _shared/repositories/analysis-repo.ts → upsert_website_analysis RPC
Atomic upsert via Postgres RPC upsert_website_analysis — upserts the website_analyses row and replaces all analysis_items in one transaction. Business status updated to ANALYZED. CostTracker records token usage and provider costs.
ANALYZED CostTracker: provider=gemini, model, tokens
19 SALES GENERATION PIPELINE generate-sales/index.ts → SalesService
Triggered by "Generate Sales" button → separate endpoint:
  1. Load Analysis — getFullAnalysis(businessId) joins analysis_items
  2. Offer Matcher — scores all offers against analysis (Industry +30, Weakness ×15 max +45, Capability gap +20, Tech gap +15, AI alignment +20, Lead score bonus +10) → Top 3
  3. Gemini Call — model gemini-2.5-flash, temperature 0.4, timeout 60s
  4. Post-Validate — selected offer must be one of the Top 3 (fallback to highest-scored if not)
  5. Advisory Lock — Postgres advisory lock prevents concurrent sales generation for the same business
  6. Content-Hash Cache — SHA-256(aggregate_hash|offer_slugs|language) → returns cached result if identical
  7. Save → generated_messages table (email, whatsapp, cold_call_script, follow_up_sequence, urgency)
Output format: "Subject: ...\n\n{body}" for email | JSON.stringify() for cold_call_script
20 Save Urgency _shared/repositories/analysis-repo.ts:192 → saveUrgency()
If the sales generation was NOT cached and a proposal (urgency) was generated, writes it to the latest website_analyses row. This method was missing pre-Phase 1.9 and caused the entire sales endpoint to crash. Now implemented and functional.
21 Response _shared/response.ts → success() / error()
Standardized response format:
Success: { data: <payload>, error: null }
Error: { data: null, error: { message: "...", code: "ERROR_CODE" } }
All responses include X-Request-ID header for tracing.
22 Frontend Display hooks/use-business.ts → TanStack Query → Components
On success, the React Query mutation invalidates relevant query keys (['businesses'], ['business', id], ['dashboard-stats']), triggering a refetch. The hook useBusiness normalizes website_analyses (handles object-vs-array from PostgREST), sorts by created_at. Components re-render:
  • LeadWorkspace: ScoreExplainer, BusinessSnapshot, AnalysisDetails, SalesAssetsModals
  • Pipeline: Filters by priority tier + next_action segment
  • Dashboard (Command Center): Today's Execution counts + Opportunity Segments via Priority Engine + Next Best Action
  • Toasts: sonner — success/info/error with human-readable messages per error code
23 Logging & Observability _shared/observability/
Structured logging at every step: request.started → analysis.started → analysis.cached_hit or gemini.analyze_success → analysis.priority_computed → analysis.completed or analysis.failed. CostTracker records per-request token usage. API usage tracked in api_usage table. All logs include X-Request-ID, userId, businessId.

🔌 Edge Functions — Endpoint Reference

10 Supabase Edge Functions (Deno runtime) and their roles.

POST import-businesses

Batch import via Google Places Text Search. Creates businesses + health scores + import sessions. Rate limited 100/day.

POST enrich-business

Scrape business website (5 pages), run 8 detectors, persist contacts/capabilities/technologies.

POST analyze-business

Full AI analysis: profile → Gemini → priority → save. Caches by aggregate hash. Rate limited 50/day.

POST generate-sales

Offer matching → Gemini sales copy → email/WhatsApp/cold-call/follow-up. Advisory lock prevents concurrency.

GET businesses

List businesses for a project. Joins categories, cities, contacts, capabilities, analyses, messages. Auth required.

GET import-sessions

List import sessions for a project. Auth + ownership check on project.

GET/POST/PUT/DELETE projects

Full CRUD. Auth enforced. All ops scoped by owner_id. Auto-set owner_id on create.

GET sales-assets

Fetch generated messages for a business or project. Joins businesses + offer_templates.

GET health

System health check. verify_jwt: false — open to all. Reports API usage + provider health.
